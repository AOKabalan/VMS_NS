Reviewed 2026-10-22. Committed target: `dad7b55fb56aeac13e2220f6a6f3d9cd17d6baf6`. File/line references below refer to that commit unless marked **Phase 8 working tree**. The unfinished OSS diff and its new `oss_projections.py` were inspected separately; the five known rule-5 config failures are excluded.

## Verdict

The committed discretization implements the specified ASGS equations, adjoint sign, stabilization parameters, splitting, and time-level bookkeeping correctly on inspection and in the completed checks below. There is a reproducible Picard failure-path hang, a pressure-gauge discrepancy, and material gaps in what the temporal and steady-state verification tests establish. The unfinished Phase 8 lagged solver follows the specified equations, but independent frozen-advector spectra confirm that this iteration is too slow or divergent in relevant cases. I recommend coupled projection unknowns for Phase 8, while retaining the nonlinear-subscale outer iteration and strengthening the tests before treating Phases 0–7 as fully verified.

## Spec conformance and code structure

The following checks were re-derived from the equations and traced through the code, rather than inferred from comments or prior acceptance reports.

- **Adjoint and signs.** Elementwise integration by parts of subscale convection, viscosity, and continuity gives `−a·∇v − νΔ_h v − ∇q` after the specified boundary/divergence omissions. Substituting `ũ=τ_t(f−D_tu−L_a(u,p)+H)` into `+(ũ,L*_a)` gives positive SUPG/PSPG products with `D_tu+L_a−f−H`. `operators.py:19–26` and `vms.py:83–89` implement this, including the negative P2 viscous energy product. The sign mutation fails U4 and U5 decisively.
- **Parameters.** `stabilization_parameters.py:12–24` uses the shortest cell edge, `4k⁴ν/h² + 2k|a|/h`, and `τ_c=h²/(4k⁴τ_m)`. There is no time-step term in τ_m. `time_stepper.py:364–371` selects τ_m for static and `(α₀/δt+τ_m⁻¹)⁻¹` for dynamic subscales. Switching off the pressure subscale removes τ_c.
- **Switches/splitting.** Only ASGS is admitted at HEAD. Dynamic ASGS includes both history in the closure and `(D_tũ,v)` with the subscale expression substituted. For nonlinear splitting, `a=u+ũ*` reaches convection, residual, adjoint, and both parameters; boundary advection remains `u`. The local inverse is `(I+τ_t∇u)⁻¹` with the correct τ factor. The stored iterate is frozen only during the inner solve; the FE residual is reassembled after its update. The approved global infinity-norm local stopping rule and omission of a one-Picard-step outer mode are recorded Phase 7 decisions, not new findings.
- **Quadrature.** Production forms, outer norms, and quadrature storage use the same default q=3k rule. Error diagnostics use 2q. Reference-rule positivity and nonpolynomial sampling tests are substantive. The separate degree-6 exact-solution solenoidality sanity check is outside the discrete solve and does not affect subscale coupling. The U2 coverage gap is R5.
- **Time schemes.** BDF coefficient moments give exactness through degrees 1, 2, and 3; the implemented rows are `(1;1)`, `(3/2;2,−1/2)`, `(11/6;3,−3/2,1/3)`. For CN, `w=(gⁿ+gⁿ⁺¹)/2` gives `D_tg=(2w−2gⁿ)/δt` and `gⁿ⁺¹=2w−gⁿ`. `time_schemes.py:29–65`, `time_stepper.py:220–229,309–332`, and `subscale_storage.py:27–41` consistently use each step's coefficients, including lower-order startup and zero negative-time subscales for exact-history startup. CN always begins with BDF1, averages forcing and Dirichlet endpoint data, extrapolates both dynamic states, and retains pressure at the half time. Pressure diagnostics use that time. The exact pressure in V2 is identically zero, however, so V2 alone cannot detect evaluation of exact pressure at the wrong time; the separate VTK test checks time labels.
- **Newton/Picard.** The true residual always evaluates τ at current `u(+ũ*)`. For frozen-τ Newton, differentiation precedes replacement of the frozen velocity, dropping only τ derivatives; the residual itself is not frozen. The 16 finite-difference Jacobian tests cover degree, dynamics, splitting, and τ options. Picard freezes all advectors and τ, including the outflow advector, while retaining the transported velocity unknown. The solver exception/control-flow defect is R1.

Against plan §§3, 5, and 6, the core uses small equation functions, dataclasses, and stateful solver/storage/output classes without inheritance or an unnecessary abstraction framework. Symbols in the formulation layer follow the spec. No concrete dead-code or core module-boundary defect warranting a finding was identified. Production physical norms use `assemble`; algebraic residuals and local maximum changes use global PETSc vector norms, not local NumPy reductions. NumPy reductions in the quadrature module operate on the fixed reference rule. The convergence-study driver is explicitly serial per README and the Phase 4b deviation; its unsupported two-rank launch is therefore not counted as a defect in the supported MPI solver.

## Phase 8 assessment

The working diff has the correct reduced OSS residual: it removes `D_tu` from both the closure and ξ's projected quantity, retains forcing, viscosity and dynamic subscale history, and uses τ_t for ξ and τ_c for ζ. `WeightedProjection` uses consistent mass and unconstrained collapsed FE spaces, with no Dirichlet conditions or pressure-nullspace constraint on either projection. The outer solver updates the projections and reevaluates the FE residual before accepting convergence. I found no sign or weight defect in these additions that would explain away the iteration failure. The existing acceptance tests have not yet been extended with U6 or OSS variants; the implementer's reported monolithic convergence rates were not independently rerun here.

For fixed advection and τ, write the homogeneous error equations as

```text
A x + B y = 0,       C x + M y = 0,
x = (u,p),          y = (ξ,ζ),
M = diag(M_τt, M_τc).
```

One exact FE solve followed by exact projections gives `y_next = T y`, where `T=M⁻¹ C A⁻¹ B`. A well-posed coupled matrix does not imply `ρ(T)<1`. Coarse pressure has no time mass, so reducing δt need not repair the troublesome projection/pressure iteration. This explains why monolithic accuracy and a divergent segregated iteration can coexist; it is a solver issue, not evidence against the OSS equations.

I assembled this error matrix independently using the committed spatial operators, static reduced-residual OSS equations, and a frozen interpolant of the exact Re=40 Kovasznay advector. The domain is `[−0.5,1]×[−0.5,1.5]`, with homogeneous velocity error on every boundary, one pressure coefficient removed solely as a gauge, unrestricted ξ/ζ, shortest-edge τ, and q=3k. The FE time-mass coefficient is `1/δt`. Dense eigenvalues and repeated applications of T show the same slow decay or growth.

Thus the reported ≈0.85 P1 behavior and divergent refined P2 behavior are plausible and reproducible. “Independent of δt” should be qualified to the tested regime: the P1 radius rises toward one for the smaller time step above. Nor does every P2 mesh diverge.

There are cheaper changes worth distinguishing from a robust default:

1. **Projection relaxation is a real stabilizing fix for the reproduced negative P2 mode.** With relaxation ω, eigenvalues become `1−ω+ωλ`; ω=1/2 moves −1.186 to −0.093. However, it also moves the positive slow mode to 0.992742, requiring roughly 2,530 iterations for an eight-decade error reduction. It worsens the P1 contraction too. This is a useful diagnostic or fallback experiment, not a practical replacement for the present outer loop. A different case with a positive real eigenvalue above one could not be stabilized by ordinary positive under-relaxation.
2. **Lag the full-residual projection as in Colomés.** It has the same fixed point but different iterates. The additional term is `−τ_t(α₀/δt)(u_i−u_previous)` in the subscale. Independent probes improve P1 at δt=0.005 from 0.972738 to 0.923447, but the refined P2 radius remains divergent at 1.195202. Restoring that source iteration therefore does not solve the general problem.
3. **Anderson acceleration can reuse the existing FE/projection solvers**, and is a reasonable alternative if coupled LU memory becomes limiting. It still needs history management, scaling, safeguards, and tests across static/dynamic and P1/P2 cases; no acceleration timings or convergence guarantees were established in this review.

**Recommendation: option 1, coupled projection unknowns.** It removes the demonstrably poor splitting while preserving the prescribed consistent weighted projection and discrete orthogonality. Codina §2.3 explicitly describes the coupled algebraic system and its Schur condensation; Colomés §5.2.2 likewise identifies implicit treatment of the projection within the linear system as an alternative. These are statements about solving the equations, not a guarantee of performance for this implementation. [Codina 2008](https://www.scipedia.com/wd/images/d/dc/Draft_Samper_877243328_2104_Pl289.pdf), [Colomés et al.](https://www.oriolcolomes.com/publication_preprints/preprint_CMAME_2015.pdf).

For this small direct-solver code base, add ξ (and ζ only when active) to the inner unknown and retain the existing outer iteration for nonlinear ũ*. Differentiate all required cross-block terms; frozen-τ Newton must still freeze only τ derivatives and retain a true coupled residual. Apply the pressure null space only to physical p, keep projections unconstrained, and retain common quadrature and CN history/extrapolation. Extra unknowns approximately double the field count when both projections are active; LU memory/fill is the tradeoff to measure. If that later becomes expensive, consistent-mass Schur actions can avoid an explicitly enlarged solve, but explicitly forming the global mass inverse is not local condensation and would undermine the project's current simplicity.

Before accepting Phase 8, add U6 with variable weights/nonzero boundary values and an assembled orthogonality check, extend U5 and V1–V4 as planned, compare a small coupled solution against fully converged lagging where lagging converges, and check all startup/CN cases. Keeping the original unaccelerated lagging unchanged (option 3) would leave documented supported configurations unable to meet the convergence requirement.
